# AI Paper Reading Study

## 파일 역할

* `index.html`: 페이지 구조와 메뉴
* `style.css`: 디자인
* `posts.js`: 발표 기록, 요약, PDF 경로 및 주제 키워드
* `members.js`: 멤버 소개
* `app.js`: 데이터로 화면을 만드는 코드, 주제 필터 정렬·펼치기, 검색 및 페이지네이션 (보통 수정 불필요)
* `slides/`: 발표 PDF 보관
* `.nojekyll`: Jekyll 처리 생략 (숨김 파일이 표시되지 않으면 GitHub Add file → Create new file에서 생성 가능)

## 발표자료 게시

GitHub에서 PDF와 `posts.js`를 수정하면 배포 후 반영됩니다.

1. 발표자료를 PDF로 내보냅니다. 파일명은 `2026-10-28-paper-title.pdf`처럼 영문·숫자·하이픈을 사용하세요.
2. 저장소에 `slides/` 폴더를 만듭니다. GitHub의 Add file → Create new file에서 `slides/.gitkeep` 파일을 만들면 됩니다. 이미 폴더가 있으면 생략합니다.
3. `slides` 폴더를 연 뒤 Add file → Upload files로 PDF를 업로드하고 Commit changes 합니다.
4. `posts.js`를 열고 연필(Edit) 버튼을 누릅니다.
5. `const posts = [` 다음에 아래 항목을 추가합니다. 게시물은 발표 날짜(`date`) 내림차순으로 목록에 표시됩니다.
6. 처음 실제 글을 등록할 때 기존 `example: true`인 항목을 지우면 예시 게시물과 미리보기 안내가 사라집니다.
7. Commit changes 후 Actions의 배포 완료를 확인합니다.

```js
{
  id: "2026-09-16-paper-title",
  number: "01", // 우리 스터디 회차 번호
  example: false,
  topic: ["NLP", "Retrieval", "Multilingual"],
  title: "논문 제목",
  subtitle: "부제목 (논문 자체의 부제목 또는 직접 작성한 부제목)",
  cover: "CLEAR", // 갤러리형일 때만 표시 (현재 리스트형에서는 표시 X)
  presenter: "발표자 이름",
  date: "2026-09-16", // 발표 날짜
  paper: "https://arxiv.org/abs/실제논문번호",
  author: "논문 저자 이름",
  venue: "학회 / 저널명 (예: NeurIPS 2026)",
  code: "", // 공개 코드 링크 (없으면 빈 문자열)
  pdf: "slides/2026-09-16-paper-title.pdf",
  summary: "한 문장 요약",
  discussion: `### 마크다운 형식 사용 가능
#### 1. 첫 번째 주제

논의 내용 **강조 가능**

- 리스트 작성 가능
- 리스트 작성 가능

#### 2. 두 번째 주제
`
},
```

* `id`는 글마다 다르게 작성하세요.
* `number`는 카드 표시 번호입니다. 자동으로 재정렬되지 않습니다.
* `topic`에 새 주제를 쓰면 필터가 자동으로 추가됩니다. 같은 주제는 표기를 통일하세요.
* `pdf`는 실제 파일 경로와 대소문자까지 일치해야 합니다. 경로 앞에 `/`를 붙이지 마세요.
* `summary`는 일반 텍스트, `discussion`은 Markdown으로 표시됩니다.
* `paper`, `code`가 빈 문자열이면 해당 링크가 표시되지 않습니다.
* PDF 미리보기를 지원하지 않는 브라우저에서는 PDF 열기 / 저장 링크를 사용합니다.
* `.md` 파일만 올려서는 새 게시물이 생성되지 않습니다. `posts.js`에 항목을 추가해야 합니다.

## 주제 키워드 필터

논문 아카이브 상단의 주제 필터는 `posts.js`의 각 게시물 `topic` 배열을 기반으로 자동 생성합니다. 별도의 필터 목록을 직접 수정할 필요가 없습니다.

### 키워드 등록 원칙

* **첫 번째 키워드 (`topic[0]`)는 해당 논문의 대표 키워드(Primary Topic)**입니다. 예: `topic: ["NLP", "Retrieval", "Multilingual"]`에서 `NLP`가 대표 키워드입니다.
* 두 번째 이후의 키워드는 세부 키워드로 취급합니다.
* 동일한 키워드를 여러 게시물에서 사용해도 상단 필터에는 한 번만 표시됩니다.
* 어떤 게시물에서는 세부 키워드이더라도 다른 게시물에서 첫 번째 키워드로 사용되었다면 대표 키워드로 분류됩니다.
* 키워드는 대소문자와 띄어쓰기를 통일하세요. 예를 들어 `LLM`과 `llm`은 서로 다른 키워드로 처리됩니다.

### 필터 정렬 규칙

1. `전체`는 항상 가장 앞에 표시됩니다.
2. 첫 번째 키워드로 한 번 이상 사용된 **대표 키워드**를 먼저 표시합니다.
3. 대표 키워드 내에서는 해당 키워드를 포함하는 **게시물 수가 많은 순**으로 정렬합니다.
4. 나머지 **세부 키워드**도 해당 키워드를 포함하는 게시물 수가 많은 순으로 정렬합니다.
5. 같은 분류이고 등장 횟수가 같다면 **영문 알파벳순**으로 정렬합니다.

이 정렬은 `posts.js`의 게시물 순서와 무관하며, 게시물을 추가하면 자동으로 다시 계산됩니다.

### More / Less

* 기본적으로 **`전체` + 키워드 6개 = 총 7개**의 필터만 표시합니다.
* 키워드가 6개를 초과하면 `+ More (N)` 버튼이 나타납니다. `N`은 기본 표시에서 생략된 키워드의 개수입니다.
* `+ More (N)`을 누르면 전체 키워드가 표시되고, `− Less`를 누르면 다시 접힙니다.
* 숨겨진 키워드를 선택하고 목록을 접어도 **선택된 키워드는 항상 표시**되어 현재 적용된 필터를 확인할 수 있습니다. 이 경우 화면에 필터가 일시적으로 7개보다 하나 더 표시될 수 있습니다.
* 키워드 선택 시 게시물 필터링과 페이지네이션은 기존과 동일하게 작동하며, 검색도 함께 사용할 수 있습니다.
* 기본 표시 개수를 바꾸려면 `app.js`의 `FILTER_LIMIT` 값을 수정하세요. 이 값에는 `전체`가 포함됩니다.
* 키워드가 6개 이하라면 `More` 버튼은 나타나지 않습니다.

## 멤버 소개 수정

`members.js`에서 각 사람의 따옴표 안 값을 수정합니다.

```js
const members = [
  {
    name: "첫 번째 이름",
    school: "대학교 이름",
    department: "학과 이름",
    github: "https://github.com/계정명",
    email: "name@example.com"
  },
  {
    name: "두 번째 이름",
    school: "대학교 이름",
    department: "학과 이름",
    github: "https://github.com/계정명",
    email: "name2@example.com"
  }
];
```

빈 값은 입력 예정으로 표시됩니다. GitHub는 새 탭에서 열리고 이메일은 기본 이메일 앱으로 연결됩니다. 이름·이메일 등에는 실제 공개할 정보를 넣으세요.

## 공동 운영

저장소 Settings → Collaborators에서 GitHub 계정을 초대하면 함께 수정할 수 있습니다. 동시 수정 충돌을 줄이려면 서로 다른 브랜치에서 편집 후 Pull request로 합치거나, 번갈아 수정하세요.

## 문제가 생기면

* 사이트가 안 열림: Settings → Pages의 브랜치와 `/(root)`, 루트의 `index.html`을 확인합니다.
* 수정이 안 보임: Actions의 배포 완료를 확인한 뒤 Ctrl+Shift+R로 새로고침합니다.
* 게시물이 모두 사라짐 / `posts is not defined`: `posts.js`의 쉼표, 따옴표, 백틱, 대괄호 등 **JavaScript 문법 오류**를 먼저 확인합니다. 개발자 도구 Console의 첫 오류 메시지가 원인일 수 있습니다.
* PDF 404: 경로와 파일 이름 및 대소문자를 확인합니다.
* GitHub 웹 업로드 파일 한도는 파일당 25 MiB입니다. 더 큰 PDF는 압축하거나 Git으로 올리세요. 일반 Git 저장소는 100 MiB 초과 파일을 차단합니다.
